# 模块说明文件模板

每个模块说明文件命名为 `AGENTS.<模块名>.md`，与根目录 `AGENTS.md` 平级（或放入 `docs/` 目录，二选一，项目内保持一致）。

## 模板结构

```markdown
# <模块名> 模块说明

> 一句话职责描述（从包注释/README/代码归纳）。

- **目录**: `<相对路径>`
- **包名/语言**: `<package name>` / `<language>`
- **文件数 / 符号数**: N / M（来自分析输出统计）

## 功能点清单

| # | 功能点 | 关键符号 | 位置 |
|---|--------|----------|------|
| 1 | <功能描述> | `FuncName` / `TypeName.Method` | [file.go:L120-L145](../path/file.go) |
| 2 | ... | ... | ... |

## 核心类型

| 类型 | 说明 | 位置 |
|------|------|------|
| `Foo` | <用途>；关键字段 `A`(L11) `B`(L15) | [foo.go:L10](../path/foo.go) |

## 对外接口（导出符号）

| 符号 | 签名 | 说明 | 位置 |
|------|------|------|------|
| `DoThing` | `func(ctx, id) error` | ... | [svc.go:L33](../path/svc.go) |

## 依赖与协作

- 依赖包: `xxx/yyy`（用途）
- 被谁调用: <模块/入口>

## 备注

- 特殊约定、坑、TODO
- 复杂度信号：大文件/大函数提示（如 `svc.go` 800+ 行、`SaveMatchData` L638-L805 约 170 行）
- deprecated 符号与替代方案
```

## 编写规则

1. **Go 行号必须来自 goast 输出**，禁止凭猜测填写；`line`/`end_line` 即 `[file.go:L<start>-L<end>]`。结构体可从 `fields` 摘 2-4 个关键字段及行号写入"核心类型"说明列。
2. **字段级引用统一格式**：`` `Type.Field`(L<n>) ``（反引号包裹、行号紧跟圆括号），例如 `` `Player.KungfuId`(L81) ``。verify.py 按此格式做字段级校验，禁止写成 `[Type.Field](file.go:L81)` 或散文形式。
3. **非 Go 行号来自 codeindex.py 时**，引用前必须打开文件核实；无法逐一核实时标注"约"（如 `file.ts:L120（约）`）。
4. 链接使用**完整相对路径**（从项目根起，如 `[projectA/module1/sub1/handler.go:L222](...)`），禁止裸文件名（同名文件会导致校验歧义）；行号以 `L<n>` 锚点表示。
5. 功能点按"用户视角/业务视角"归纳，不是逐函数罗列；多个相关函数可归并为一条功能点，列出关键符号及行号范围。
6. 导出符号表只列对外有意义的接口；getter/setter、测试辅助可省略。
7. 测试文件（`_test.go` / `*.test.ts`）不列功能点，但可在备注中说明测试覆盖入口。
8. "依赖与协作"同时写正向依赖（我 imports 谁）与反向协作（谁调用我），跨模块处链接到对方的 `AGENTS.<模块名>.md`。
9. HTTP 接口表与定时任务表优先取自 ast.json 的 `routes` / `crons`（goast 自动提取），不必人工翻 main.go/task 文件。
